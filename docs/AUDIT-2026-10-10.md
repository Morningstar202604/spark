## 本次修复清单

### [P1] LangGraph 路径工具未执行（严重功能缺陷）
- **文件**: `src/spark/core/graph.py` + `src/spark/core/loop.py`
- **影响**: 启用 `_use_graph=True` 时，工具调用被完全忽略，ReAct 循环只能执行一轮
- **根因**: 图结构为线性（llm→tools→END），外层 while 循环未传递状态；tools 节点仅检查批准但未实际执行工具
- **修复**:
  1. tools 节点改为调用 `registry.execute()` 实际执行工具
  2. 图结构改为循环（tools→llm→tools→...→END）
  3. 添加条件路由 `_route_errors` 检查 `_error`、`tool_results`、`rounds`
  4. tools 节点追加执行结果到 history 确保下一轮 LLM 可见
  5. LLM 节点的异常分支也重置 `tool_results` 防止无限循环
  6. 外层 `_iter_turn_graph` 改为单次 `astream` 调用（由 LangGraph 管理循环）
  7. 处理 `chunk["tools"]` 为 None 的边界情况

### [P1] server.py boot_mcp asyncio.run 崩溃风险
- **文件**: `src/spark/web/server.py`
- **影响**: 若 EventLoop 已存在，`asyncio.run()` 抛出 RuntimeError
- **修复**: 新增 `_run_coroutine_safe()` 工具函数，检测到已有 EventLoop 时切换到线程执行

### [P1] server.py base_url 路径拼接问题
- **文件**: `src/spark/web/server.py`
- **影响**: 用户配置 `base_url="https://api.deepseek.com"` 不带 `/v1` 时 API 调用 404
- **修复**: 规范化 base_url 确保以 `/v1` 结尾

### [P2] sandbox.py 命令注入防护不足
- **文件**: `src/spark/sandbox.py`
- **影响**: `_command_tokens` 使用黑名单过滤，可被 `||`、`$(...)`、反引号绕过
- **修复**: 添加 `||`、`\r`、`\t`、`$(`、反引号到过滤列表

### [P2] config.py import re 在函数体内
- **文件**: `src/spark/config.py`
- **修复**: 将 `import re` 移模块顶部

### [P2] cli.py 类型注解不完整
- **文件**: `src/spark/cli.py`
- **影响**: 39 处 `Optional[T]` 未升级为 `T | None`，8 处 `cfg` 参数无类型注解
- **修复**: ruff 自动修复 + 手动添加 `SparkConfig` 类型

### [P3] config.py _sanitize_project_config 信任边界不严
- **文件**: `src/spark/config.py`
- **影响**: 恶意项目的 `.spark.toml` 可覆盖 `context.agents_md` 指向项目外文件
- **修复**: 强制将 `agents_md` 重写为默认值 `"AGENTS.md"`

### 异常处理

⚠️ **全局广泛使用 `except Exception:` / `except Exception as exc:`** — 共 60+ 处，主要集中在：
- `web/server.py` — SSE 事件循环（合理）
- `core/loop.py` — 工具执行、子任务（合理）
- `core/graph.py` — LLM 节点（合理，防止图崩溃吞掉错误）
- 大多数已正确记录或转为 `turn_error` 事件

建议：对 SSE 断开等预期错误保留宽泛捕获；对配置解析、路径验证等使用精确异常类型。

### asyncio 使用

- **11 处 `asyncio.run()` 调用** — 主要在 `cli.py` CLI 入口点（安全）
- **2 处 `new_event_loop()`** — `core/loop.py` 用于同步适配器，`mcp_bridge.py` 用于跨线程调度（合理）
- **1 处 `_run_coroutine_safe`** — 本次新增，使用线程+独立 Loop 方案
