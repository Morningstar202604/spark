# Spark 文档

## 项目概述

Spark 是一个本地运行的终端编程 Agent，参考 OpenAI Codex CLI 的 Agent Loop，把「读代码、改代码、跑命令、再推理」做成可自托管、可换模型、可审批的精简产品。

开发者在仓库目录执行 `spark`，用自然语言交代任务。Spark 在本机完成推理循环，按审批策略读写文件、执行 shell，并把会话落到本地。不依赖 ChatGPT 登录、厂商套餐或云端 Agent 服务。

**目标用户**: 希望自己掌控模型、密钥与代码边界的个人开发者与小团队。

**核心价值**:
- 本地优先：代码、会话、审批记录留在本机
- 模型可换：OpenAI 兼容 API 与本地模型（Ollama 等）用同一套配置切换
- 核心可控：Agent Loop、工具、三级审批、会话与 MCP 都是一等公民，可改可扩

## 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 语言 | Python 3.11+ | 迭代快，LLM SDK 与 MCP 生态成熟 |
| 交互形态 | 终端 TUI（Textual） | 对齐 Codex CLI 的终端体验：对话、diff、审批 |
| CLI 入口 | Typer | 子命令清晰，`spark` / `spark exec` 易扩展 |
| 配置 | TOML + pydantic-settings | 人类可读，类型校验，环境变量覆盖密钥 |
| LLM 接入 | OpenAI 兼容 Chat Completions | DeepSeek、通义、OpenRouter、vLLM、Ollama 共用一套客户端 |
| 会话存储 | SQLite | 零运维，支持恢复会话与检索历史 |
| 工具协议 | 函数调用 + MCP | 内置读写文件/shell；外部工具走 MCP |
| 测试 | pytest | 循环、审批、工具、会话可用纯 Python 测通 |

## 核心功能

### Agent Loop
- **目的**: 把用户任务拆成「推理 → 工具 → 观察 → 再推理」直到给出最终回复
- **描述**: 与 Codex 同源：模型要么结束本轮，要么发起工具调用；Spark 执行工具、把结果写回上下文，再请求模型

### 内置工具
- **目的**: 让 Agent 能在工作目录里真正改代码
- **描述**: 读文件、按路径写入/补丁、列出目录、执行 shell；每一步受工作区边界与审批策略约束

### 三级审批
- **目的**: 开发者自己决定自动化程度
- **描述**: Suggest（改文件与命令都确认）、Auto Edit（自动写文件，命令需确认）、Full Auto（在工作区内自动执行）

### 模型提供方
- **目的**: 甩掉厂商账号与套餐
- **描述**: 配置 `base_url`、`api_key`、`model`；同一套配置可指向云厂商兼容接口或本机 Ollama

### 会话记忆
- **目的**: 任务可中断、可恢复
- **描述**: 每轮消息、工具调用与审批结果写入 SQLite；启动时可 `--resume` 继续；项目根的 `AGENTS.md` 作为持久指令注入

### MCP
- **目的**: 用标准协议接外部工具，避免把所有能力写进内核
- **描述**: 从配置拉起 MCP stdio 服务器，把其 tools 合并进模型可调用集合，调用同样走审批
